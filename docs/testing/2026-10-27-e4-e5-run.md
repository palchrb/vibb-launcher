## Emulator facts learned

- **Unticking an app under Device › Apps uninstalls it** (`AppInstaller.uninstallSilently`, by design). An off/on toggle
  of Fennec as the "nudge" removed Fennec, and one of Element X removed Element X (re-sideloaded). Nudge with a setting
  instead: "Download apps on Wi-Fi only" off and on (`POST /devices/1/app-updates`). The phone sends a status report with
  every sync.
- Android's app-op pages write the **uid** mode; `cmd appops get` prints it as `Uid mode: OP: allow` above the package
  mode (`default`). The launcher's raw read follows it.
- A battery-exempt Etar keeps Settings' "Alarms & reminders" switch off; AlarmManager shows the exemption in `dumpsys
  alarm` ("User exemption list appids").
- Android's Settings is `hidden=true` outside a pause (its pages don't resolve from `am start`); with our PIN lock up,
  lock task refuses them (error 101). `dumpsys package <pkg>` prints nothing for a hidden package: read `dumpsys package
  packages`. Android kept Element X's `POLICY_FIXED` camera flag across an uninstall and reinstall.
- A manifest-only APK (`aapt2 link --manifest ... -I platforms/android-36/android.jar`, `apksigner`) is a quick test app
  for declared permissions; it needs "Allow these apps" like any sideload.
- `uiautomator dump` keeps the old file when it fails: delete `/data/local/tmp/ui.xml` first. The lock's windows are
  secure (black screencap) but dump fine.
- The launcher's policy puts the screen timeout back to 60 s; `svc power stayon true` keeps the screen on (back to
  `false` at the end).
- The parent code wasn't known: set to 13572468 under Lock › Parent PIN (stays on the test phone).
- The calendar provider takes the shell's writes (events, reminders, calendars as a sync adapter); `--bind` values with a
  colon need `\:`. `DayActivity` isn't exported. About 365 quick `input swipe`s take a minute and move ~280 days.
- ICSx5 needs its calendar access granted on its own start card; until then its sync fails silently. From adb:
  `requestsync -n "'Calendar subscriptions'" -t at.bitfire.icsdroid -a com.android.calendar -F --is --ib --ex`.
- A device's own time rules need "Own rules" on (`POST /schedules/device/1 section=switch custom_schedule_enabled=on`);
  deleting a phone's rule needs `scope=1`.
- A "System UI isn't responding" dialog right after boot (swiftshader); "Wait" clears it.

## Findings for a fix round

- **H1 (High) - the reminder row's tap never opens Dagen.** `launcher/.../lock/GlanceOpener.kt:141` starts
  `DayActivity.intent(activity, day)` from `PinLockActivity` without `FLAG_ACTIVITY_NEW_TASK` (the missed-calls path has
  it, `PhoneBookActivity.missedCallsIntent`). Dagen lands in the pinlock task and is destroyed with it:
  `01:24:23.624 START u0 {cmp=.../DayActivity (has extras)} ... from uid 10217 (sr=51387434)` (the PinLockActivity),
  `GlanceOpener: Glance: opened Dagen`, `wm_finish_activity: [0,51387434,54,...PinLockActivity,finish-activity]`,
  `wm_destroy_activity: [0,164090753,54,...DayActivity,finish-imm:finish-activity]`, `Attempted to add application window
  with unknown token ... DayActivity t-1`. Reproduced at 01:25:13. The kid ends on Home.
- **M1 (Medium) - the header's date line is clipped at font 1.3** (Dagen's `KidHeader` subtitle "October 27", bounds
  `[105,99][456,126]`, the bottom of the glyphs cut; screenshot `w3-dagen-font13.png` in the session scratch). In the
  same pass the time column wraps "All day" to two lines.
- **M2 (Medium) - Etar's first start outside a pause crashes** after its runtime dialogs: it asks
  `android.settings.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, Settings is hidden, `ActivityNotFoundException` at
  `AllInOneActivity.checkAndRequestDisablingDoze(AllInOneActivity.java:452)`. §6v step 4's "first start works with no
  pause" fails; the second start works. Etar's bug - the fix is ours to choose: the docs/the PWA line say "start Etar
  once in the pause", or the battery exemption first (which also grants its exact alarms).
- **M3 (Medium) - system apps get "App access" rows on the phone**: Camera (`WRITE_SETTINGS`), Clock (FSI), Messages
  (`SCHEDULE_EXACT_ALARM`), Phone (`WRITE_SETTINGS`, FSI), each "Approved - pause first to change it". The report leaves
  system apps out (the code QA's L2) but `accessEligible` doesn't; a real phone with Google's apps allowed gets a long
  list of rows a parent can't change.
- **L1 (Low) - the 10 dp peek of the neighbour days doesn't show**: at rest the screen edges are background up to x=23
  and the cards start at x=24 on both sides (`w2-dagen-tomorrow.png`); the neighbour pages' margins swallow the peek.
- **L2 (Low) - a sideways swipe on the reminder row acts as a tap** and opens "Enter your code to open Dagen" (twice);
  the row stays, as designed, but a message row's swipe dismisses it while this one opens a keypad.
- **L3 (Low) - each App access trip asks the parent code again**: leaving Settings for Android's page ends the gate
  (`onStop`), so "turn on <app>'s switch, then come back" comes back to the code dialog.
- **L4 (Low) - Dagen's times have no AM/PM in a 12-hour locale** (en-US here): "12:38" is 00:38 in one row and 12:38 PM
  in another, "11:08 - 12:38". The new-event day reads "Tuesday October 27" (no comma).
- **L5 (Low, docs) - §6v/§6w steps that need words**: §6v step 1's "Settings' camera switch locked by the admin" can't be
  reached (Settings is hidden outside a pause and the pause lifts the denial); §6w step 4's hide rule must be moved above
  the "Starts with" rule (first match wins); §6w step 5: ICSx5 syncs only after its own calendar-access card is granted
  in the pause; §6w step 1: colons in `--bind` values need `\:`.
