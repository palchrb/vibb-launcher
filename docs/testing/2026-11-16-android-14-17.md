# Android 14 to 17: Vibb One and Vibb music (2026-11-16)

The first check against the standing rule "every change works on Android 14-17" (root `CLAUDE.md`, "Supported
Android"). The build was main at cd0f8ff59, with both debug builds and lint run. It was a static review plus a smoke on
API 34 and API 37.2. API 35 and 36 are covered by the daily `six35` and `jelly36` work.

## Android 17

Android 17 has been stable since 16 June 2026 as **API 37**. Its QPR1 is 37.1 and its QPR2 is 37.2. The sources are
developer.android.com/about/versions/17 (`behavior-changes-all`, `behavior-changes-17`, `release-notes`,
`changes/bg-audio`) and developer.android.com/work/versions/android-17. Nothing official changes Device Owner, lock
task, roles, foreground service types, exact alarms, Modes, VPN or call screening.

## Smoke

- **API 34** (UE1A.230829.050): `scripts/smoke-test.sh` 20 pass, 1 fail, 8 skipped. The fail is the PIN unlock: the
  script swipes from the handle at the very bottom, which 14 takes as Home. Home, the shade with Snarveier, the lock
  glance, a time rule's lock with Do Not Disturb, Kid Settings, music and calls all worked.
- **API 37.2** (CP41.260831.015, 16 KB pages, 3-button navigation): 16 pass, 4 fail. Every fail matches system_server
  crashing in the emulator's graphics stack (mapper.ranchu `hasReadColorBufferDma` on any CPU readback: screencap, the
  handle's colour sampling, task snapshots), not our code. Checked by hand: the missed-call notification posts, and
  music plays under its media foreground service. The 37.0 image was unusable for the same graphics bug.

The screenshots, logs and the API scan are in the session scratchpad (`compat/`), not in the repo.
