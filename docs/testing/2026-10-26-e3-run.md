## Design 67 - "DNS can't be reached" (checks 13-15)

| Check | Result |
|---|---|
| 13. Two unreachable servers | **PASS**: custom `tls://192.0.2.10` + backup `tls://192.0.2.11`; four look-ups over 70 s all "unknown host"; `UpstreamReach: Upstream unreachable, failures=5` 48 s after the first failure. The phone reports only at a sync (a nudge or the schedule), so the line appeared at the next nudge: "Testtelefon · DNS can't be reached since 19:47 - neither your server nor the backup answers" (`unreachable_since_ms` = the first failure, 18:47:34Z). Backup changed to `https://1.1.1.3/dns-query` (rev 3): `Upstream outage ended` at once, names resolve, and the next report gives "Backup server since 19:56 - can't reach your server from where the phone is · couldn't be reached 19:47-19:56" - the ended line survives the rev change (9 min, above the 5-min floor) |
| 14. Offline is no outage | **PASS** with `svc wifi disable` **and** `svc data disable` (the emulator has a cellular network too - Wi-Fi off alone still resolves): three look-ups over 45 s fail, no `Upstream unreachable`; after enabling both, names resolve. The outage of check 13 was already over, so the "loss of the validated network ends an outage" rule was not exercised |
| 15. Provider mode blocked | **PASS**: Cloudflare in force, the host's `iptables -I OUTPUT -d 1.1.1.0/24,1.0.0.0/24 -p tcp --dport 853/443 -j REJECT` (+ udp 443; the emulator's traffic leaves as the host's): four failed look-ups, `Upstream unreachable, failures=5`, and after a nudge "Testtelefon · DNS can't be reached since 20:13 - Cloudflare doesn't answer from where the phone is" - the only phone line in provider mode. Rules removed afterwards (`iptables -S OUTPUT` has no REJECT). The first attempt's block lasted 2.5 min and its ended outage was rightly not shown (under 5 min) |

## Emulator facts learned

- The phone sends `dns_upstream` and the queued blocked-domain events only with a status report, and a report comes at a
  nudge or the schedule: nudge with a real policy change (a blocklist override, an allowlist tick). Re-saving the custom
  server with the same values nudges nothing, and toggling the phone's log off clears its queue.
- `svc wifi disable` is not offline on this image; `svc data disable` too.
- A sideloaded APK must match the image's ABI (`INSTALL_FAILED_NO_MATCHING_ABIS` for Fennec's armeabi-v7a build
  1580200; 1580210 is x86_64, 1580220 arm64).
- `run-as me.vibb.launcher.debug cat shared_prefs/me.vibb.launcher.debug_preferences.xml` shows the debug launcher's
  stored policy and flags (`dns_log_enabled`, `mdm.dns_upstream_custom`, the queued events).

## Verdict

Design 67's resolver side behaves as designed on `jelly36`: the built-in hosts, the canary, our own upstreams by name,
the outage window with its 5-min floor, offline, provider mode and the rev-change survival. Owed to a device with a
screen: Chrome's `chrome://policy` (check 9), Fennec's DoH modes (11), the other browsers (16-17), WhatsApp's
READ_PHONE_STATE (L2). **Tag `server-v0.56.0` and `launcher-v0.37.0-rc.6`.**
