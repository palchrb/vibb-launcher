## Findings

**M1 - The mark's 48 dp hit area is cut at the bottom** (Medium; design §5.5, launcher QA H1). The `TouchDelegate` sits on
`lock_glance_top`, but with the card folded that view ends exactly at the mark's bottom (`lock_glance_top` bounds
[0,48][480,297], the own-line mark [48,262][138,297]; at font 2.0 the row ends at 268 too). A TouchDelegate only sees
touches inside its host, so nothing below the mark opens the card: measured, the own-line mark reacts from y=243 to 297
(54 px = 36 dp) instead of 48 dp; taps 1-3 px below it miss. Sideways the 8 dp extension works. *Fix:* host the delegate on
a view that contains the extended rectangle (e.g. `lock_glance_scroll`'s child or the glance root), or give
`lock_glance_top` a bottom padding of the missing half (moving the rows down by that much), and extend
`LockGlanceLayoutTest` to check the rectangle lies inside the host's bounds.

**M2 - A zone chosen right after the phone's last try waits up to 55 min** (Medium; design D5, the R1 gap). The PWA invites
exactly this: the parent turns the weather on (or changes Location), sees "No fresh position and no zone", and picks a zone.
The zone save only nudges; `WeatherPull.afterSync` consumes the nudge flag (`nudge.getAndSet(false)`) even when
`weatherPullDue` refuses it because the last try is under `WEATHER_NUDGE_GAP_MS` (3 min) old, and a `no_position` answer
stamps `pulledAtMs`, so screen-ons wait for the 55-min rule. Seen: tried 20:12:07, zone saved 20:12:40, screen-on at 20:17:20
pulled nothing; only a second save at 20:17:48 brought the weather. *Fix:* keep the nudge pending until a pull actually
runs (honour it at the next screen-on or sync once the gap has passed), and/or don't stamp `pulledAtMs` for
`no_position` (let the 5-min try gap govern), with a `WeatherModelTest` row for "zone saved 30 s after a no_position".

**L1 - A period without hours is spoken as a bare label** (Low). The card's description reads "Morgen: Ettermiddag:
Delvis skyet. ..." - "Morgen:" followed by nothing, run into the next period (shown as "–"). *Fix:* skip the period
in `spokenCard` when it has no symbol and no temperature, or add a sentence like "Ingen varsel." / "No forecast."

**L2 - At font 2.0 on the Jelly Star "Ettermiddag" breaks mid-word** (Low). The part label has `maxLines=2`, so
"Ettermiddag" wraps as "Ettermi / ddag", and that column's symbol and degrees sit a line lower than the other two. The foot
also drops the place there (by the code QA L6 rule; fine). *Fix:* a soft hyphen in the nb string ("Etter­middag")
with `hyphenationFrequency="normal"`, or `maxLines=1` with uniform auto-size, and a fixed two-line label height so the
three columns stay aligned.

**L3 - The first answer for a new cell has no place for up to an hour** (Low; as designed in D13, noted for the user).
Kartverket is asked after the answer, so the first pull for a cell has `place: null` and the card's foot shows only
"1° / 6°" until the next pull (~55 min); both Oslo and Bergen showed it. *Fix (optional):* when an `ok` answer has
`place: null`, let the phone pull once more after a few minutes, or let the server wait ~1 s for a lookup it starts.
