## Tables

- `admin_users` - parent login accounts, TOTP secret (+ `totp_last_step`), forced-password-change flag, TOTP failure counter and lock (`lock_count`, `locked_until`), `session_epoch`, `reauth_wrong` (0086: wrong passwords in a row at the re-auth forms); several equal accounts per family since design 62 (0087: `display_name`, `invited_by`, `invite_expires_at` - a one-time password's 72 h, `removed_at` - a soft remove; `docs/notes/server/connectivity.md`, "Parent accounts"), `lang` (0104, design 70: the PWA's language, `en`/`nb`, NULL until the first signed-in request), `webauthn_user_id` (0116, design 74: a passkey's user handle, 16 random bytes made at the first add), `passkey_only` (0118, design 74 step 2: no password, no TOTP, at least one passkey - read an `AdminUser` through `admin_select!()`, which adds its `passkey_count`); `admin_passkeys` (0116: a parent's passkeys - the COSE key, its RP ID, the counter, BE/BS; `docs/notes/server/connectivity.md`, "Passkeys")
- `devices` - one row per kid's phone: name, enrollment code hash + kind (+ expiry, cleared on use; `enrollment_code` itself is always NULL since 0052), hashed bearer token, enrolled/last-seen timestamps, `avatar_hash` (0100: the phone's own picture, the PWA's alone and never sent to the phone - `photos::DEVICE_AVATARS` in `data/device_avatars/`, backed up like the contact photos; uploaded from the summary's header to `POST /devices/{id}/avatar` (`/avatar/remove`), served **without a session** at `GET /phone-avatars/{hash}` (only a hash a phone names; the admin gate applies - with `ADMIN_PUBLIC=on` the hash is the only guard; never on the phones' listener) because it is also a push's icon; `docs/notes/server/pwa.md`, "A phone's own picture"), `avatar_tone` (0138, design 85: the phone's own colour until a picture is set, an index into `devices::AVATAR_TONES`, picked inside the new phone's `INSERT` by `devices::next_tone` and never moved; `docs/notes/server/pwa.md`, "Every phone's own colour")
- `device_policy` - one row per device: `lock_wake_on_notification` (launcher round 7 §3, 0084: Lock Screen & PINs' "Wake the screen for a notification", sent as `launcher_ui.lock_wake_on_notification`), `lock_notice_alert` (design 130, 0173: Av / Vibrer / Lyd in the cell under it, `off`/`buzz`/`sound`, sent as `launcher_ui.lock_notice_alert`; design 82 W3's `lock_buzz_on_notification` (0136) before it, mapped and dropped by 0173), allowlist JSON, `custom_schedule_enabled` (the Own limit switch: its own `daily_budget_json` instead of the global one; until 0115 also its own rules instead of everyone's - since then `device_rule_off` per rule), `location_mode`/`location_interval_minutes`, the frozen pre-step-6 schedule columns, `kiosk_desired` (always `1` now), `lock_task_features` (bitmask), `override_pin_hash`/`override_pin_salt`, `kid_pin_hash`/`kid_pin_salt`/`kid_pin_length` (step 10; the Child PIN, the PIN of Android's lock), `kid_pin_sealed`/`kid_pin_prev_sealed`/`kid_pin_prev_rev`/`kid_pin_rev` (design 59, 0085; its `kid_keyguard` dropped by 0181, design 132 - `docs/notes/server/hardening-and-pins.md`, "Android's lock screen")
- `global_schedule` - singleton (`id = 1`): the global `daily_budget_json` and the frozen pre-step-6 schedule; `time_rules` (device_id NULL = global), `device_rule_off` (0115: a rule switched off for a phone) and `time_lifts` - see "Time rules" above
- `device_status` - append-only heartbeat log (pruned after 48 hours since 0.57.0, each phone's newest report from before them kept): lock reason, kiosk-engaged, installed-app snapshot, app version, timestamp, `offline_override_used`, `policy_state`, `restrictions_paused`, `capabilities_json`, `call_state_json`, `time_state_json`, `lock_state_json`, `update_fence_json`, `notification_cancels_json`, `backup_service_enabled`, `relock_json`, `unseen_boots_count`/`_last_at_ms`, `foreign_access_json`, `relock_blocks_json` (design 24b), `zone_watch_json` (design 64 step 2, 0092), `vpn_filter_json` (design 116, 0158: the web filter `up`/`down`/`off`, `mobile_network::clean_vpn_filter`)
- `security_events` / `banned_ips` - admin login audit trail and lockout tracking (180 days, a phone's own lines 30/90, an expired ban at once - `docs/notes/server/retention-and-crashes.md`); since 0.54.0 also `settings_saved`, a parent's saves coalesced per page for 10 minutes (`settings_log`, `docs/notes/server/pwa.md` "The rest of Settings")
- `tracked_apps` - one row per app in the global catalog (including the launcher itself, `is_launcher`), GitHub-sourced, manually-uploaded or from an F-Droid repo (`source_type` `fdroid`, `fdroid_repo`/`fdroid_package` since 0094; `docs/notes/server/play-and-updates.md`, "F-Droid source"; `latest_release_version_code` since 0139, the stored release APK's own versionCode, `app_updated`'s check - `docs/notes/server/notifications.md`, "App update notices"; since 0141 (design 90) the served release's declared permissions, the sensitive ones the parent accepted, "Ask me before every update", the app's wait in hours, the release waiting it out and the one declined - `docs/notes/server/play-and-updates.md`, "Update holds and the per-app wait") - see the "Apps tab"/"global catalog" bullets above; `tracked_app_held_releases` (0141) - the one release per app held for the parent's approval, its file next to the served one; `tracked_app_seen_releases` (0141) - when this server first saw each listed release (the wait counts from the later of it and the source's time); `fdroid_repo_keys` (0111) - a custom F-Droid repo's signing key, pinned at its first fetch; `fdroid_repo_state` (0112) - every F-Droid repo's newest entry.json timestamp taken
