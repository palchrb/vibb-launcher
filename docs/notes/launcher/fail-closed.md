# Launcher notes: fail closed

Moved from launcher/CLAUDE.md on 2026-11-27 (the "Fail closed" section in full; the core keeps a summary); the core file's 'Where the rest is' lists every note.

## Fail closed

`AppEnforcer.apply(null)` means "no restrictions", so a "no usable policy" case (a corrupt cache, a server answering a default policy after an error) must never become `null` on a managed phone:
- **`server/PolicyGate.kt`** (pure, no Android imports, `PolicyGateTest`): `decodeCached` (Absent/Ok/Corrupt), `decodeFresh`, `judgeFresh` (rejects a fresh policy with `allowlist == null` when the phone was managed - cached allowlist present, cache corrupt, or cache missing although `policy_ever_applied` is set), `judgeCached` (a cached policy without an app list on a managed phone counts as unreadable, `Corrupt(NO_ALLOWLIST)`: "managed" is the `LastEnforcedPlan` written with it having an app list, or missing/unreadable although `policy_ever_applied` is set; one without `call_policy` while `calls_managed_last` is set too, `Corrupt(NO_CALL_POLICY)`, its `appsManaged` only when it has an app list - `judgeFresh` reads a `Corrupt`'s `appsManaged`, so a phone with unmanaged apps still takes a fresh policy without one; `cachedPolicy()` and `TimeRulesStore` read the cache through it), `choosePolicy` (fresh > cache; `Apply(null)` only on a phone that has never applied a policy, so setup works; otherwise `Fallback`), `policyState`, `shouldSuspendNewPackage`.
- **`Fallback` enforces the `LastEnforcedPlan`**: a tiny separate JSON (allowlist, kiosk, lock-task features, schedule) stored in `last_enforced_plan` with every accepted policy. If that's unreadable too, the fallback is "nothing allowed, kiosk on". So an override or pause that ends while the cache is unusable re-locks on the next sync instead of staying open.
- **`performMdmSync`** fetches the raw body (`MdmApi.getPolicy()` returns `ResponseBody`): no network = unreachable, 5xx = `server_error` (the server answers 500 instead of a default policy), undecodable = `fresh_decode_failed`. Only an accepted fresh policy is cached - together with `policy_ever_applied` and the `LastEnforcedPlan`, in one synchronous `commit()` (`storeAcceptedPolicy`) - and only then do the PIN hash, command dispatch and uninstalls run. Every status report carries `policyState` (`ok`/`cache_corrupt`/`rejected_suspect`/`fresh_decode_failed`/`server_error`), shown as a warning on the server.
- **`cachedPolicy()` returns `CachedPolicy`**; offline callers use `currentPolicyDecision()` (`reevaluateLockReasonFromCache`, the Settings pause switch, `AppEnforcer.enforceOnNewPackage`), and `KidSettingsActivity` only reads an `Ok` cache (`controlsSection`).
- **The enrolment's witness** (`server/EnrolmentWitness.kt`, device-protected storage): a phone that was managed is
  never read as new when its preferences are lost - its `policy_applied` counts as "a policy was applied"
  (`everManaged`: Fallback, the Settings gate), and with it or `enrolled` no first-launch reset runs and Koble til with
  its emergency button is due, for the witnessed server only (`docs/notes/launcher/setup.md`).
- **`allowlist = []` means nothing allowed**: every controllable package except our own (and the system dialer, below) is suspended and hidden, and kiosk pins only our own package (it's HOME and holds LockActivity/Settings). `null` still means unmanaged.
- **The system dialer is never suspended or hidden, managed or not** (`TelecomManager.getSystemDialerPackage()`, `computeEnforcementPlan`'s `neverRestrict`; `apply()` also force-releases it if an older build left it hidden): it's the in-call UI for emergency calls. Unsuspended, its keypad would bypass the allowlist (any number, MMI/USSD, call forwarding), so **while managed and the dialer isn't allowlisted, `apply()` sets `DISALLOW_OUTGOING_CALLS`** (before releasing the dialer; emergency calls are exempt) and `AppFilter` leaves the dialer off Home and the app list while that restriction is set. It's cleared when unmanaged or under an override. Keeping the dialer out of the lock-task packages does **not** keep it out of kiosk: with `LOCK_TASK_FEATURE_KEYGUARD` set, AOSP's `LockTaskController` lets any system-dialer task run (its emergency-call exemption), e.g. via a `tel:` link - the call restriction is the real gate. Keyguard is forced on with kiosk on the launcher side too, not only by the server.
- **`DISALLOW_CONFIG_DATE_TIME` (plus automatic time) while managed**, lifted under an override like every other restriction, so the clock can't be moved to stretch a schedule.
- `ServerJson` lives in `server/ServerJson.kt` so JVM tests don't load Retrofit. It has no `coerceInputValues`: one `null` in a non-nullable field fails the whole decode (`PolicyResponseCompatTest`); the server's `policy_json_keys_snapshot` test keeps that from happening.
