## Findings
1. **M, L `calls/MissedCallNotifier.kt:157`, `calls/MissedCallNotice.kt:115`, `calls/DialerRole.kt:19`: rules==null with our role held means no notification at all.** Telecom defers to our receiver, which only cancels. This happens in UnknownFailClosed. It also happens when calls are Unmanaged after the role came from the system prompt: `takenByUs=false` gives `RoleAction.NONE`, so we keep the role. Before this commit Telecom posted its own notification. **Fix:** release on Unmanaged even when the prompt granted the role. With rules==null, post a count-only notice of the unread missed rows whose tap is the call-log VIEW (phone book, or passed on while unmanaged).
   **Fixed (count-only notice); the release part skipped.** With no managed rules (`rules == null`), `plainMissedCallNotice` posts "N tapte anrop" (no names) from the log's unread missed rows (`MissedCallsRepo.unreadMissed`: count, newest `_id`, date - never numbers). The same id rules apply (bound, alert once per newer id, swipe/dismiss mark read); it is never marked read automatically. Its tap, like every tap now, is the call-log `VIEW` sent explicitly to `PhoneBookActivity`: the phone book, or, while unmanaged, passed on to the system dialer (that also dismisses ours). Reading those ids and marking them read is allowed while calls are managed **or** our dialer role is held (`canKeepMissedCalls`), because Telecom gives that duty to the default dialer. Releasing a prompt-granted role on Unmanaged is skipped: `dialerRoleAction` keeps a role the parent chose by hand on purpose (step 2, `DialerRole.kt`), and changing that is the user's decision, not this step's.
2. **L, `calls/MissedCallNotifier.kt:69`: the 5 s echo rule.** Inside the window it can't hide a call: count 0 only ever cancels, and the window only skips a cancel. Telecom's broadcasts reach us in send order, so an echo only trails a broadcast X that Telecom queued just before our cancel. If that echo lands more than 5 s late (load, boot), it cancels X's post. X stays unread (badge, next broadcast or boot), so it is delayed, not lost. **Fix:** use ids, not the clock. Persist the bound of the last `markReadAndResetTelecom`, and ignore count 0 while `shown_up_to_id` is above it. Or ignore count 0 entirely, since dismiss and Clear already cancel ours.
   **Fixed** (ids). `markReadAndResetTelecom` persists `reset_up_to_id`. Count 0 cancels ours only when `zeroCountCancels(shown_up_to_id, reset_up_to_id)`, i.e. ours shows nothing newer than the last reset. The 5 s window is gone.
3. **L, `calls/MissedCallNotice.kt:115`: Clear marks read in a narrowed view.** Calls off or a no-calls time rule leaves emergency contacts only, so `notice==null` gives `Clear(bound)`. That marks every unread missed row read, e.g. Mom's from just before school, through the after-call pass of an emergency call. After the window ours never shows it again; only the badge does. **Fix:** pass `markReadUpToId = null` when `!rules.callsEnabled`, so it only cancels.
   **Fixed.** `noticeStep(mayMarkRead = rules?.callsEnabled == true)` reads the effective rules, so a no-calls time rule counts as calls off. Calls off, a time rule, fail-closed or unmanaged now only cancel ours.
4. **L, `calls/PhoneBookActivity.kt:119`: `passOnCallLog` calls Telecom on the main thread.** It calls `TelecomManager.getSystemDialerPackage` (binder) from `onCreate`/`onNewIntent`. **Fix:** cache the package in CallPrefs at the hand-back (`AppEnforcer` already looks it up there), or resolve it in a coroutine before `finish()`.
   **Fixed.** `applyDialerRole` (every `apply()`, background) caches the system dialer as `CallPrefs.systemDialer` (written only when it changes). `passOnCallLog` reads the cache and makes no binder call. With nothing cached yet it logs and doesn't pass the intent on.
5. **L, `calls/MissedCallNotifier.kt:108`: `cancelOurs` leaves `shown_up_to_id` set.** Once calls are managed again, the first phone-book open marks that stale range read and resets Telecom. **Fix:** reset it in `cancelOurs`.
   **Fixed.** `cancelOurs` sets `shown_up_to_id = 0`.
6. **L, `calls/MissedCallNotifier.kt:26`: only one after-call pass, at 3 s.** If Telecom writes the log later, an answered call from that contact leaves ours up until the next trigger. **Fix:** add a second pass at about 10 s, or a CallLog ContentObserver while ours is shown.
   **Fixed.** After-call passes run at 3 s and 10 s. They still only update or clear, and queued passes coalesce.
7. **L, `calls/MissedCallNotifier.kt:212`: a swipe should mark read; a deleteIntent is worth it.** Telecom's own notification (`ACTION_CLEAR_MISSED_CALLS`) and AOSP Dialer both mark read on swipe. A deleteIntent fires only on swipe or Clear all, never on the auto-cancel tap or our own cancel. The badges keep their seen model, so nothing is lost. **Fix:** `setDeleteIntent` with an explicit broadcast to a new receiver (not exported, not direct-boot-aware) that runs `goAsync` + `MissedCallNotifier.dismiss` (bound `shown_up_to_id`). Extend `MissedCallManifestTest` and drop the known limit.
   **Fixed.** `setDeleteIntent` sends an explicit broadcast to `calls/MissedCallDismissReceiver` (`exported="false"`, not direct-boot-aware, no filter; `goAsync`). The bound is the post's own (`EXTRA_UP_TO_ID`), not the current `shown_up_to_id`, so a late swipe can't mark a newer post read. `MissedCallNotifier.swiped` marks that range read and resets Telecom. It clears the state only when nothing newer was posted since (`swipeClearsShown`). Tested in `MissedCallManifestTest` and `MissedCallNoticeTest`. The known limit is gone.
