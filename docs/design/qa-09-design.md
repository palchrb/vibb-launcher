# QA/security review - design 09 (SMS allowlist + fixes)

Code checked on `handy` (L minSdk 34). Severity: P0 = blocks emergency, guarantee or fail-open; P1 = must fix before implementing; P2 = fix or document.

## Findings
1. **P0 - B4 (emergency).** `LockActivity.kt:101-103` falls back to `ACTION_DIAL tel:112` when `placeCall` fails. That intent goes to the default dialer. With calls unmanaged during a school rule, the system dialer is deliberately not pinned (`EnforcementPlan.kt:174-181`), so with BLOCK_ACTIVITY_START_IN_TASK the fallback ends on BlockedAppActivity. **Change:** fallback = explicit `ACTION_EMERGENCY_DIAL` to the resolved emergency-dialer component, which must be in `lockTaskHelpers`. Same audit for every emergency path (PhoneBookActivity 112 dialog, keyguard button).
2. **P0 - B4 (helpers incomplete/wrong).** Missing: PermissionController (`pm.permissionControllerPackageName`: runtime permission dialogs in allowed apps, plus `createRequestRoleIntent`, which is the dialer/SMS role fallback at `HomeActivity.kt:328` and would never work in kiosk); Telecom (`com.android.server.telecom`: UserCallActivity/EmergencyCallActivity for `ACTION_CALL*`, call error dialogs). Wrong: on API 34+ the share sheet is `com.android.intentresolver`, not `android`. Package names for photo picker, DocumentsUI and cell broadcast (`com.google.android.cellbroadcastreceiver` vs `.module` vs OEM) differ per device. **Change:** resolve helpers at apply via intents (`ACTION_EMERGENCY_DIAL`, `ACTION_CHOOSER`, `ACTION_OPEN_DOCUMENT`, `MediaStore.ACTION_PICK_IMAGES`, permission controller, Telecom, CB receiver of `SMS_CB_RECEIVED`). Accept only FLAG_SYSTEM packages. Keep pure `lockTaskHelpers(resolved, state)` with a test that Settings, Play, GMS, GSF and the launcher-visible Camera never appear unless already allowlisted.
3. **P1 - B4 (call-rule regression).** The design adds the "system dialer" to helpers unconditionally. That undoes 02/06: when calls are managed or the rule blocks calls, the system dialer is not pinned (`EnforcementPlan.kt:174-181`). **Change:** helpers never include the system dialer. Its pinning stays under the existing rule. Emergency is covered by the dialer component from #1.
4. **P1 - B4 (lock-out kill switch).** The bit is OR'd in unconditionally, so a device-specific breakage (emergency, IME, in-call, alarm full-screen intent) cannot be undone remotely. **Change:** server flag `block_activity_start` (default on) feeds `serverLockTaskFeatures`, shown on the Push and Play card. The parent PIN exit and LockActivity stay in our package (already pinned). Test alarm ringing and the IME in kiosk with the bit set.
5. **P0 - B1 (fail-open warnings).** The pending rule also fires when `call_state.state` disagrees with `calls_managed`. If the phone never takes the role, every later report disagrees, so the role/SMS warnings are hidden forever behind "Waiting...". **Change:** pending only while `reported_at < roles_changed_at` and `now - roles_changed_at < 5 min`. After that, show the real warnings plus "phone hasn't confirmed since HH:MM". A newer report that disagrees is a warning, never pending.
6. **P1 - A3/B2 (process kill on handback).** `QuickControls.selfGrantPermission` returns early if the permission is already granted (`QuickControls.kt:127-131`). Once a role has granted a permission, the self-grant is skipped, so it is never POLICY_FIXED and the role revoke kills us (A1 last row). The list "SMS + READ_CONTACTS" is also too narrow: ROLE_SMS and the dialer role also grant phone, storage/media, mic, camera and notifications. **Change:** new `fixOwnPermission` keyed on `dpm.getPermissionGrantState(...) != GRANTED`. Apply it to every runtime permission we request that either role grants, before TAKE. If DPM refuses hard-restricted SMS permissions, don't rely on survival: after RELEASE, Home's cold start must re-enter kiosk (#acc D5).
7. **P0 - A3 (role lost = fail-open).** `restrictSms(CONTACTS && !held)` is evaluated only in `apply()`. After an OTA, a package update or a RoleManager re-evaluation, SMS goes to the new holder (or `SMS_RECEIVED` goes to system apps) until the next sync. **Change:** handle `Telephony.Sms.Intents.ACTION_DEFAULT_SMS_PACKAGE_CHANGED` (sent to old and new holder), `MY_PACKAGE_REPLACED` and boot (`BootCallPolicy`). Each sets `DISALLOW_SMS` first, then applies. `SmsDeliverReceiver` blocks unless the persisted mode is CONTACTS and the state is readable (no implicit accept). Use `goAsync`.
8. **P1 - A2 (spoofing).** "ALLOW if sender is an emergency number" opens a spoof channel: any SMS gateway can send as 112/113, and Norway sends no SMS from 112. **Change:** remove that clause and rely on the callback window only. Document the residual risk on the calls page: numeric senders, including approved contacts, can be spoofed, and alphanumeric senders that look numeric go through normalize.
9. **P1 - A3 (rebroadcast leak).** The permission denials skip system apps, but ISH re-broadcasts `SMS_RECEIVED` (and data/port SMS, non-MMS WAP push) to every RECEIVE_SMS holder. That includes GMS, whose SMS Retriever/User Consent API hands the full body of a blocked SMS carrying an app hash to any allowed app. **Change:** state this as a residual risk ("blocked SMS bodies may reach apps using Google SMS verification"). The page lists allowed apps that request SMS-retriever-style permissions. Never claim "blocked = nobody sees it".
10. **P1 - A5 (mode silently ignored).** `restrictSms` returns false for `Unmanaged` (`EnforcementPlan.kt:144-148`), and the design ties CONTACTS to managed calls (A6, window/call log). The default `'contacts'` then shows "Approved contacts" while the phone is open. **Change:** the radio is disabled with "needs managed calls" unless calls are managed, the server stores and sends the effective mode, and there is one source of truth (derive `sms_enabled` on read, no second column write).
11. **P1 - A6 (handback hygiene).** Re-set `DISALLOW_CONFIG_DEFAULT_APPS` in the same pass after TAKE/RELEASE (`applyDialerRole` clears it). `setDefaultSmsApplication` blocks up to 5 s and the dialer setter up to 20 s, so neither may run on the main thread, including apply from Home/pause/recheck. If `prev` doesn't qualify or is uninstalled, try Messages, then keep `DISALLOW_SMS` and warn.
12. **P2 - A3 (class 0 / STK / MMS).** Class-0 (flash) SMS goes through `decideIncomingSms` like any other and is never shown before the decision. Suspending `com.android.stk` doesn't stop SIM-initiated SMS (modem/telephony) and breaks SIM BankID: document both. Group MMS from an allowed contact with unknown members: placeholder only, never fetched.
13. **P2 - A4 (privacy).** Message notifications use `VISIBILITY_PRIVATE` with a public "New message" version. No body in logcat, `SmsEventLog`, crash reports or the server (sender, time, kind only). Note that Google backup copies the SMS provider. Don't show the body in the shade during a time-rule lock.
14. **P2 - B2 (camera).** `KEYGUARD_DISABLE_SECURE_CAMERA` does nothing without a PIN. If Camera is allowlisted, LTC lets it start and the BLOCK bit doesn't help, so that bullet is misleading. **Change:** say it plainly (no-PIN plus allowlisted camera means only the runbook gesture-off helps). `setKeyguardDisabledFeatures` ORs with existing flags. Keep "diagnose first".
15. **P2 - B4 (helper surface).** Pinning PermissionController, DocumentsUI and intentresolver lets allowed apps reach their pages (app permissions, default apps, "open with"). Verify that policy-fixed grants, `DISALLOW_CONFIG_DEFAULT_APPS` and BLOCK on onward starts hold.

## Acceptance criteria
- [local] L: `lockTaskHelpers` resolves from an injected intent→package map. Never contains Settings/Play/GMS/GSF/system dialer. Contains emergency dialer, Telecom, permission controller and CB receiver when they resolve to FLAG_SYSTEM.
- [local] L: `decideIncomingSms` vectors: contact, alphanumeric, withheld, "112" sender (BLOCK), window open (ALLOW), state unreadable (BLOCK), mode != CONTACTS in the receiver (BLOCK). `decideOutgoingSms`: rule, override, 112.
- [local] L: `fixOwnPermission` decides on the DPM grant state, not on `checkSelfPermission`. Its permission list ⊇ the role-granted permissions we request.
- [local] L: the role-change handlers set `DISALLOW_SMS` before apply. CONTACTS with calls unmanaged gives a defined plan (test).
- [local] S: pending expires after 5 min. A newer disagreeing report shows warnings. The SMS radio is disabled when calls are unmanaged. Old launcher gets `sms_enabled=false` for contacts.
- [device] D1: kiosk + BLOCK, school rule, calls unmanaged, CALL_PHONE revoked: LockActivity emergency reaches the emergency dialer (test mode, never real 112). Keyguard emergency button works too.
- [device] D2: CB test alert appears in kiosk. Runtime permission dialog of an allowed app works. Share sheet, photo picker and file picker work. Alarm rings. Settings opened from a pinned helper is blocked.
- [device] D3: server flag off → bit cleared on the next apply.
- [device] D4: after TAKE, `dumpsys package <ours>` shows no runtime permission with the role-granted flag that isn't POLICY_FIXED. ON→OFF→ON gives no `am_kill`.
- [device] D5: if a kill happens anyway, Home cold-starts back into lock task within 5 s with no camera or other app on top.
- [device] D6: `cmd role add-role-holder android.app.role.SMS <messages>` (adb) → `DISALLOW_SMS` set within seconds. Texts from C are not shown anywhere in the UI.
- [device] D7: SMS spoofed as "112" (emulator `sms send 112`) is blocked. Class-0 from C is not shown.
- [device] D8: an app using SMS Retriever receives a blocked hashed SMS → recorded as residual (document, no fix).
