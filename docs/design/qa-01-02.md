# QA/security review of designs 01 (own build) and 02 (calls)

Reviewer: QA/security, 2026-10-04. Pre-implementation. Does not repeat `docs/review/qa-security.md`.
Severity: **blocker** = must change before implementing/shipping that step; **should-fix** = change in the same PR
series; **note** = document or test. Threat model: a motivated 10-14 year old with time and physical access, who
can read our GPLv3 source; plus a network attacker.

## Findings

1. **blocker. 01 §3.2 (empty allowlist) + 02 §2.2.** Today `AppEnforcer.kt:98-130` suspends **and hides** every
   controllable package not allowlisted, and the system dialer is controllable (system app with a launcher icon).
   01 widens this to `allowlist = []`, and 01 ships before 02's carve-out. 02 keeps "may be suspended when
   unmanaged". So between 01 and 02, and forever on unmanaged phones, the preloaded dialer (the only in-call UI for
   emergency calls, 02 §1) can be hidden. Required: move "systemDialer is never hidden and never suspended,
   managed or not" into 01's `computeEnforcementPlan`, with a unit test. Answer 02 open question 3 with "never".
   Add an emergency-path device check to 01 §4 step 8/9.
2. **blocker. 02 §2.1 PSAP window.** The window opens for any number that `isEmergency` accepts, and that function
   ORs a static list that includes `000`, `08`, `118` and `911`/`999`. A kid dials `08` or `000` (the call fails or
   goes nowhere, and costs nothing). That makes stranger calls, withheld ones included, ring for 60 min. The window
   can be reopened at will. Required: open the window only when **the platform** says the number is an emergency
   number **and** the call connected (CallLog `TYPE_OUTGOING`, `DURATION > 0`). Keep the static list only for
   ALLOW-outgoing when the platform API throws, cut down to the country's real set. Report every emergency call and
   window opening in `callState`, and have the server alert the parent. Test: `08` or `000` does not open the window.
3. **blocker. 02 §2.1 `CallPolicyStore` vs §2.6.** The table says "managed before and now absent → fail closed". The
   store says `Ok` with `callPolicy == null` → `Unmanaged`, which releases the role and clears `DISALLOW_SMS` and
   `DISALLOW_OUTGOING_CALLS`. Any policy without the key (a server rolled back to a pre-migration build, a buggy
   build, a forged response) silently unmanages calls. 01's `judgeFresh` only checks `allowlist`. Required: our server always sends `call_policy` once it has the schema, with an explicit `"managed": false` for "not managed"; `judgeFresh` gets REJECT_SUSPECT when `call_policy` is absent, the cached policy had one, and `calls_managed_last` is set; say where `calls_managed_last` is written: in the same `commit()` as the cache, and only from an explicit `managed` value.
   Prefer keeping the **last managed rules** (separate pref) over emergency-only, so parents can still call.
4. **blocker (release gate). 02 §2.5 BFU.** "Reboot and don't unlock" is a trivial, repeatable bypass: anyone can
   call and the kid answers from the lock screen. Implementing v1 is fine, but task 15 (direct-boot call path) must
   be done before the phone goes to the kid. Mark it so in the task table and in PLAN.
5. **should-fix. 02 §2.1 outgoing backstop.** `disconnect()` in `onCallAdded` races Telecom. Calls from system apps
   whose CALL_PHONE we leave alone (Assistant, Contacts, Messages, STK, Bluetooth HFP redial/voice dial, Telecom's
   missed-call "Call back") may reach the network: C gets a ring or a missed call, which is a signalling channel.
   Required: add a pre-dial gate with `CallRedirectionService` (ROLE_CALL_REDIRECTION, granted at provisioning with
   `cmd role add-role-holder`, verified in `callState`; Telecom skips it for emergency calls). Keep the
   InCallService backstop. Its 5 s timeout fails open, so it answers from memory like screening.
   Acceptance: C's phone never rings and never shows a missed call (see 02-T10).
6. **should-fix. 02 §2.2 + §2.3. The system dialer is a free keypad.** When managed, it is unsuspended and added to
   `kioskPackages`. `DialerActivity` handles only `DIAL`, so `VIEW tel:` (Linkify in Element X, browsers) and
   Chrome `intent://…component=<dialer>` links open the system keypad, and in kiosk too. From there the kid gets
   MMI/USSD (`*21*`, `**61*`, carrier top-up and "call me" USSD), call history call-back, voicemail and Phone
   settings → call forwarding/barring. None of these pass `decideOutgoing`. Required: add `VIEW tel:`/`voicemail:` and `CALL_BUTTON` filters to `DialerActivity` and check which handler wins; do **not** add the system dialer to `kioskPackages`. LockTaskController already permits it for emergency when KEYGUARD is set, so make the launcher force KEYGUARD whenever kiosk is on, not only the server; device-test every reachability path above; if the keypad is reachable and MMI executes, this becomes a blocker.
7. **should-fix. 02 §2.1, rejected calls → voicemail.** `setRejectCall` gives C busy, and the carrier then forwards
   to voicemail. C can leave messages, and the kid hears them via the voicemail number, visual voicemail, or the
   carrier's notification SMS. That is inbound from a non-allowlisted number. Required: a provisioning step that
   disables conditional forwarding to voicemail (`##004#`, by the parent), or block the voicemail number unless it
   is allowlisted. Add UI text warning that directory/connect services (`1881`, `1880`; the design's own example)
   can put calls through to any number.
8. **should-fix. 02 §2.2 `DISALLOW_SMS`.** It does not cover RCS: Google Messages chats over data with any number.
   Required: when `sms_enabled=false`, also force-suspend the default SMS app or Google Messages (and STK, which can
   send SMS/USSD) whatever the allowlist says, and warn on the server when they are allowlisted. Checklist 9 must
   test an RCS-capable recipient.
9. **should-fix. 02 §2.6 override/pause.** "ALLOW everything" under pause, while pause is still not PIN-gated
   (qa-security #5; not in 01's scope), means Settings → pause opens all calls. Required: 02 depends on pause being
   PIN-gated and reported. Recommended answer to open question 1: pause/override lift app restrictions but keep the
   inbound allowlist; outbound may open under override only.
10. **should-fix. 02 §2.1, crash fails open.** Both services run in the main process. If `Application.onCreate` throws (the crash handler calls `exitProcess(1)`, `Application.kt:110`), screening never answers (5 s → allow) and the InCallService bind fails (→ preloaded dialer, no backstop). Required: the services must not depend on the heavy init. Guard it, or give the call path its own `android:process` with a minimal init; the initial `@Volatile state` must be `UnknownFailClosed`, never `Unmanaged`; device-test with an injected startup crash. Also note the gap while a self-update replaces the APK.
11. **should-fix. 01 §3.2 `choosePolicy`/`judgeFresh`.** `Absent` → `Apply(null)` (open), and with a `Corrupt` cache `judgeFresh` accepts a fresh `allowlist: null`. Both fail open on an enrolled phone. Required: a `policy_ever_applied` flag (written with the first accepted cache). When it is set, treat Absent like Corrupt (`KeepCurrentState`) and reject a null allowlist against a Corrupt cache too.
12. **should-fix. 01 §3.2 fresh decode failures.** A field the launcher cannot decode (the documented `"kiosk_desired": null` case) makes every fetch fail silently forever. Required: report `policyState="fresh_decode_failed"`. The server key-snapshot test also asserts that no non-Option field serialises as `null`.
13. **should-fix. 01 §1.4 CI secrets.** `workflow_dispatch` on any ref signs any branch. The keystore sits on disk while Gradle plugins, `go mod download` and third-party actions run. Put the secrets in a GitHub **Environment** `release` (required reviewer, tags only), not repo secrets. Refuse tags whose commit is not on `main` (`git merge-base --is-ancestor`). Build unsigned in one job, then sign and verify with `apksigner` in a second job that has no build tools. Pin actions by SHA, `rm` the keystore in an `always()` step, and never use `pull_request_target`. Require 2FA on the GitHub account: the repo is now the root of trust for phone self-updates and for the Pi's `curl master | bash` updater.
14. **should-fix. 01 §1.4/§1.5/§5 task 2. RC tags.** The verify step uses tag `v0.24.0-rc`, which the job's own regex rejects. If the regex is loosened instead, the RC becomes a normal release and `releases/latest` serves it to every phone through the tracked-app self-update. Required: `-rc.N` tags build as **prerelease** (never `latest`), with versionCode `…*1000+PATCH` and a separate RC range, or test only on a fork.
15. **should-fix. Rollback paths (01 §1.5, §4 recovery; server).** Launcher: a non-debuggable release cannot be downgraded (`adb install -r -d` fails), so "rollback" means re-tagging the old code as a higher patch. Say so, keep every released APK, and remember that a mistyped tag (`v9.0.0`) burns versionCodes for good. Server: `sqlx::migrate!` refuses to start an older binary against a DB that has newer migrations, and `deploy/update.sh` neither backs up the DB nor keeps the previous binary. Required: `update.sh` copies the `.db` and the old binary before the swap, and DEPLOY.md documents the rollback.
16. **should-fix. 02 §2.1/§3.4, number normalisation.** Use ASCII-only digit checks on both sides: Kotlin `isDigit()` accepts Arabic-Indic and fullwidth digits, Rust `is_ascii_digit` does not. Decide on fullwidth `＋`. Handle `sip:+47…@ims…;user=phone` handles (VoLTE / Wi-Fi calling) by taking the user part. Today that gives null → BLOCK, which blocks allowed contacts. Add vectors: `112#`, `1121234`, `112,123`, `#31#91234567`, `*31#…`, `4791234567` (no `+`), unicode digits, a `sip:` handle. Keep one shared `vectors.json` that both test suites read, not a hand-copied table. Emergency matching is exact on the stripped string, never prefix.
17. **note. 02 §2.1, spoofing.** Reject incoming with `details.callerNumberVerificationStatus == VERIFICATION_STATUS_FAILED`. Document that caller-ID spoofing of a parent's number is otherwise undetectable.
18. **note. 02 §3.3.** `ON CONFLICT(phone_number) DO UPDATE SET name` renames the contact on every device that shares it. Contact flag and remove routes must scope with `WHERE device_id=? AND contact_id=?`. The `default_country_code` CHECK `GLOB '[1-9]*'` accepts `4x`. Use `'[1-9]' OR '[1-9][0-9]' OR '[1-9][0-9][0-9]'`. Changing the CC later does not renormalise stored numbers. New POST routes inherit the missing CSRF protection.
19. **note. 01 §3.1.** A command popped for a response the launcher then rejects (REJECT_SUSPECT, decode failure) is lost: at-most-once. Acceptable, but say it, and keep `wipe`/`ring` idempotent.
20. **note. 01 §2.1 install.sh.** Validate `KPS_REPO` against `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$` before the `sed` into the root-run `actions.sh`.
21. **note. Out of scope, write it down.** Element X / Element Call VoIP and self-managed ConnectionServices bypass Telecom screening. The Matrix homeserver must restrict who can invite or call. Conference/merge: our UI has no add/merge button, and a merge by an allowed remote party cannot be prevented.
22. **note. Old launcher after new launcher.** A launcher without the InCallService loses ROLE_DIALER, so calls run unscreened, while `DISALLOW_SMS`/`DISALLOW_OUTGOING_CALLS`/CALL_PHONE denials persist. The server should alert when a device that reported `call_policy_v1` stops reporting it.

## Acceptance criteria

### 01
- **T1** [local] `assembleRelease` with a throwaway key gives a signed APK. `apksigner verify` passes.
  `aapt2 dump badging` has no `application-debuggable`. Without a keystore and with `-PrequireReleaseSigning=true`
  the build fails. `assembleDebug` is unchanged.
- **T1** [local] `EnforcementPlanTest`: the system dialer is never in `suspend` or hidden, for null, `[]`, managed
  and unmanaged (#1).
- **T2** [CI] The release job runs only for `v*` tags on `main` and only in the `release` environment. A
  `workflow_dispatch` from a branch cannot read the secrets. A wrong cert digest or a debuggable APK fails the job.
  An `-rc` tag produces a prerelease, and `releases/latest` does not change (#13, #14).
- **T3** [local] `ForkConfig` table tests (valid/invalid/missing). Without the checksum: no QR, a banner, and no
  upstream fallback. A grep of `src/` and `deploy/` finds no `siesta5787`.
- **T4** [local] Missing row, corrupt allowlist, dropped table → 500. A failed policy does not consume a command.
  Concurrent polls deliver one command once. A failed `create_device` leaves no device row. The key snapshot has
  no `null` for non-Option fields.
- **T5** [local] `PolicyGateTest`: Absent with `policy_ever_applied` → KeepCurrentState; a Corrupt cache plus a fresh
  null allowlist → REJECT_SUSPECT (#11). A fresh-decode failure sets `policyState` (#12).
- **T6** [device] The release build installs and `dpm set-device-owner` succeeds. `run-as` fails. DNS filter and
  tsnet work on mobile data. No `ClassNotFound` in logcat.
- **T6** [device] With kiosk on and `allowlist=[]`: reboot gives no deadlock, the keyguard emergency button opens the
  emergency dialer, and the preloaded dialer's in-call UI would render (emergency test mode).
- **T6** [device] Server stopped, or policy row deleted: apps stay suspended and kiosk stays on after "Sync now"
  and after a reboot.
- **T6** [device] Recovery drill: `adb install -r` of a higher-versionCode fix over a deliberately crashing build
  works. A server rollback from the update-time backup starts (#15).

### 02
- **T1/T6** [local] Both suites load the same `vectors.json`, including the #16 additions, and agree.
- **T2** [local] Our server always emits `call_policy` with an explicit `managed` (#3). The key snapshot is updated.
- **T4** [local] An invalid number gives 400 and no row. Flag/remove for a contact not attached to the device gives
  404. A missing checkbox is false. Writes nudge the device.
- **T6** [local] `CallRulesTest` (as in the design, plus): `08`, `000` and `118` do not open the PSAP window; `112` with no CallLog connection does not open it; `1121234` and `112#` are not emergency; the platform throwing still gives ALLOW for `112`; with the store state unset → UnknownFailClosed.
- **T7** [local] `judgeFresh` gives REJECT_SUSPECT on a missing `call_policy` after managed. The cached last managed
  rules still apply.
- **T8** [local] The system dialer is never in `kioskPackages`, and kiosk always carries KEYGUARD (#6).
- **T9** [device] `cmd role get-role-holders android.app.role.DIALER` shows us with no prompt. The CALL_REDIRECTION
  holder is us. `callState` reports both.
- **T10** [device] Outgoing to C from DialerActivity, from `VIEW tel:` in Element X/browser, from `am start CALL`,
  from the Assistant, from a BT headset redial and from Telecom's missed-call "Call back": all blocked, and **C's
  handset never rings and logs no missed call**.
- **T10** [device] `intent://` to the system dialer from a browser and `VIEW tel:` do not open a keypad, kiosk on
  and off. If they do, `*21*C#` and a USSD code must not execute (#6).
- **T11** [device] C, withheld C, C via Wi-Fi calling, and C after a `08` call never connect, and C cannot leave a
  voicemail the kid can hear (#7). B in national and E.164 form, and over VoLTE `sip:`, rings our UI on the lock
  screen, in kiosk and on Home.
- **T11** [device] With an injected startup crash, C is still not connected (#10).
- **T12** [device] SMS off: SMS in and out are blocked, and an RCS message to/from C is impossible (Messages
  suspended) (#8). `calls_enabled=false`: B blocked both ways, emergency still works. A third-party CALL_PHONE app
  shows "blocked by admin".
- **T13** [device] Pointing at an old/rolled-back server (no `call_policy`) keeps the last managed rules, while an
  explicit `managed:false` releases the role and clears the restrictions.
- **T15** [device], gate for handing over the phone: after a reboot, before unlock, C is rejected, and B rings with
  an answerable UI (#4).
- **All** [device] Pause without a PIN is impossible. Override keeps the inbound allowlist (#9, if adopted). The
  emergency call or PSAP window appears on the server.
