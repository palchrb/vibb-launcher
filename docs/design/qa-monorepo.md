1. **Medium** - server/src/handlers/system_update.rs:219 and :327. Pre-monorepo installs keep a schema-5 `actions.sh` that pipes `palchrb/kid-phone-server/master/deploy/update.sh`, which installs that repo's `releases/latest` (v0.18.6). An install whose binary was updated by hand with the new update.sh (the documented "Updating" command) still has that actions.sh. The next "Update now" or scheduled auto-update (`latest != APP_VERSION`) then puts the old binary on a DB that already has 0031, and `sqlx::migrate!` (main.rs:597) panics, so the server is down. Fix: don't write the `update` flag while `watcher_needs_update()` (show the reinstall hint instead). Before archiving the old repo, also replace its `deploy/update.sh` with a stub that execs the monorepo's.
2. **Medium** - .github/workflows/launcher.yml:51, server-ci.yml:22. Both jobs are named `build`, so the status-check context is the same and branch protection can't tell them apart. A required check that a path filter skips also stays "Expected" forever and blocks PRs that touch only the other component. Fix: rename the jobs (`launcher-build`, `server-build`). Either don't require path-filtered checks, or add an always-running gate job.
3. **Low** - server-release.yml:61-130. A server release runs no `cargo test`/clippy, and nothing checks that server-ci passed for the tagged commit (the launcher release does run `testReleaseUnitTest`). Fix: run `cargo test --locked` in `build` before `cross build`.
4. **Low** - server/deploy/update.sh:54, install.sh:91. The bash resolver ignores the `prerelease`/`draft` flags and relies only on the tag pattern. A `server-vX.Y.Z` release flagged prerelease by hand would be installed by bash, while the in-app check ignores it. Fix: also reject releases whose JSON object has `"prerelease": true`, or document that server releases are never flagged prerelease.
5. **Low** - system_update.rs:176/:327 and update.sh. There is no downgrade guard: "update" means `!=`, and the newest release by date wins. A backport tag or a deleted newest release would auto-install an older binary, which then refuses the migrated DB. Fix: trigger only when the semver is greater than `APP_VERSION`, and have update.sh refuse a version lower than `data/watcher_version`.
