# QA: catalog downloads and backfill nudge (472ba092, d8d459a6)

1. **Medium** - **fixed**: `AppSyncs` (one guard per app, `AppState.app_syncs`); `sync_app` answers "already running" and `sync_one_app` reads the row under the guard. "Check now" waits at most 10 s, then redirects back to the app page, which says a check is running or shows the last failure. The hourly loop skips an app that is syncing. Tests `one_sync_per_app_at_a_time`, `check_now_while_a_sync_runs_says_so`.
   Finding: one app can sync several times at once (`server/src/handlers/tracked_apps.rs:672`). "Check now" is now a detached task, so every click, form resubmit or overlap with the hourly loop starts another full download into its own `.part`, up to 1 GB each on the Pi's SD card. The request can also hang for up to 30 min. If a slower task saw an older release, it can finish last, roll `latest_release_*` back and orphan the newer file. Fix: add a per-app in-flight guard (e.g. a `Mutex<HashSet<i64>>` with a drop guard) in `sync_one_app`, and re-read the row once the guard is held. While a sync runs, Check now should say "already running".
2. **Low** - **fixed**: `remove_partial_downloads` deletes every `<dir>/*/*.part` at startup, before the scheduler starts. It replaces the 2 h rule (test `partial_downloads_are_removed_at_startup`).
   Finding: `.part` files left by a crash stay until the app's next release (`tracked_apps.rs:393`). `remove_stale_parts` runs only after a successful download. After a restart the scheduler downloads again straight away, less than 2 h after the crash, so the stale part is too new to delete, and later syncs stop at the (tag, asset id) check. Fix: delete every `data/tracked_apps/*/*.part` once at startup, before the scheduler starts, when nothing can be downloading.
3. **Low (PWA scroll rule)** - **fixed**: the Details form posts to `/apps/tracked/{id}` (`.post(update_tracked_app)`, `/edit` removed), so the 400 page keeps the scroll position. "Check now" and a successful upload now also redirect back to the page instead of rendering at `/check` or `/upload`.
   Finding: the edit form's 400 page is served at `/apps/tracked/{id}/edit` (`server/src/main.rs:372`, `templates/tracked_app_detail.html:23`). The next save, or any other form on that page, leaves from `/edit` and redirects to `/apps/tracked/{id}`. scroll-restore's path check then fails and the page lands at the top. Reloading the page gives a 405. Fix: post the Details form to `/apps/tracked/{id}` (`.post(update_tracked_app)` on that route), as the add form already does.
4. **Low** - **fixed**: an UPDATE that matches no row removes the new file (`replace_cached_file`). Delete removes the whole app directory, only after the row is gone (test `upload_replaces_the_file_after_the_update_and_delete_removes_the_dir`). The directory is now `AppState.tracked_apps_dir`, a temp dir in tests.
   Finding: deleting an app during a download orphans the file (`tracked_apps.rs:401`, `:941`). A sync that finishes after `delete_tracked_app` renames up to 1 GB into `data/tracked_apps/{id}/`, and its UPDATE matches 0 rows, so the file is never removed. Fix: remove `file_path` when `rows_affected() == 0`, and have delete remove the whole app directory.
5. **Low** - **fixed**: filters over 256 characters are refused, and a `^` filter is built with `RegexBuilder::size_limit(1 << 20)` ("too complex").
   Finding: regex size (`tracked_apps.rs:80`). `asset_pattern` has no length cap (the form body can be up to 2 MB) and uses the default 10 MiB NFA limit, so one compile can take noticeable CPU on the async worker. A compile happens once per form save and once per sync, never per device request. Fix: refuse patterns over 256 characters and build with `RegexBuilder::new(p).size_limit(1 << 20)`.
6. **Low** - **fixed**: only an `.apk` (any case) is ever picked, whatever the filter, so `^app-gplay` and `gplay` no longer pick the `.aab`. The hints say so.
   Finding: a filter can pick a non-APK ZIP (`tracked_apps.rs:92`). For example, `^app-gplay` also matches the `.aab`. An `.aab` passes the `PK\x03\x04` check and would be offered to phones, where it fails to install. Substring filters already had this problem; regex makes it easier to hit. Fix: require `.apk` for regex matches, or at least add a hint ("end with `\.apk$`").
7. **Low (pre-existing)** - **fixed**: UPDATE first, then the old file is removed, in both the sync and the manual upload.
   Finding: the old file is removed before the UPDATE (`tracked_apps.rs:395-414`). A phone that downloads in between, or a failed UPDATE, gets a 404. Fix: run the UPDATE first, then remove the old file.
8. **Low (pre-existing)** - **deferred** to `docs/design/13-app-downloads.md` (scope check + `ServeFile` with Range). `server/CLAUDE.md` no longer claims the download is scoped.
   Finding: `device_api.rs:1035` `tracked_app_download` checks only the bearer token. Any enrolled phone can download any catalog app, including disabled ones, while `server/CLAUDE.md` says downloads are scoped per device. Fix: apply the same `is_launcher OR device_tracked_apps` condition as `tracked_app_updates`.
9. **Info** - **fixed**: the backfill reuses `previous` (read before the INSERT) instead of `OFFSET 1`.
   Finding: the backfill (`device_api.rs:768`). The `reported_at DESC, id DESC` tie-break is correct (ids increase and `reported_at` has 1 s resolution). It is simpler, and does not break if the INSERT at `:654` fails (that error is ignored with `.ok()`), to reuse `previous` from `:603` instead of `OFFSET 1`. The nudge can't loop: the next report has no new package, so there is no backfill and no nudge (covered by the test `a_backfilled_app_is_allowlisted_and_the_phone_nudged`).
10. **Checked, OK**:
    - Substring filters, the launcher row and the `server-v*` skip behave as before.
    - The temp file goes on an error, a stall or overall timeout, a dropped future and a panic (no `panic = "abort"`).
    - The rename is atomic within the same directory, and the database and device API only ever see the final path.
    - The 1 GB cap is checked before each write; the ZIP header and the exact size are still enforced.
    - The device download keeps bearer auth, Content-Type and Content-Length. hyper 1.11 honours a set Content-Length on a stream body, and the launcher only reads `body.contentLength()`.
    - Migration 0042 only adds two nullable columns. Mask 7 equals the launcher's WIFI|BLUETOOTH|BRIGHTNESS.
    - `cargo test` passes at HEAD.
